## 1. 目的と対象

- 制作団体 **IDERIA**（代表: 永野斗遠）の公式サイト。「何を作っている団体か」が作品で伝わること。
- 読む人: 連携先の学校・大学関係者、コンテスト関係者、活動に興味を持った学生。
- 学習アーカイブ（https://109mei.github.io/game-learning-archive/）とは役割分担: アーカイブ=遊ぶ・学ぶ場、公式サイト=団体の顔。
- **学習アーカイブと教育用ゲームジャムの企画運営は、代表 永野斗遠が個人で行っている活動**であり、IDERIA の活動ではない。作品・活動には載せず、関連サイトからリンクするだけにする。

## 2. デザインコンセプト —「アイデアの工房」

参考にした構造: 竹書房「メイドインアビス」公式サイトのアビスガイドページ（カードを並べた一覧・縦に進む構成・ジャンプ目次・没入感）。**著作物（画像・キャラ・固有名詞・意匠の模倣）は一切使わない**。仕組みだけを借り、世界観はオリジナル。

- 世界観: アイデアが生まれて作品になっていく「工房」。ダークトーンの作業場に、作品カードが棚のように並ぶ。
- アクセントカラーは工房の灯りをイメージした暖色（アンバー＝琥珀色系）を1色決めて統一。ライトモードでも破綻しない。
- 単一ページ（`index.html`）＋データ分離（`data.js`）。依存パッケージなし・vanilla JSのみ。`prefers-reduced-motion` 対応。
- ロゴ: 当面はタイポグラフィ（文字組み）で「IDERIA」を表現。**ロゴ画像の差し替え枠**を用意しておく（`assets/logo.png` が存在すれば自動でそちらを表示する実装）。

## 3. ページ構成（上から順）

1. **ヒーロー**: IDERIA ロゴタイポ＋キャッチコピー（案: 「アイデアを、遊べるかたちに。」— 変更したければこの仕様書を修正）＋「作品を見る」ボタン。
2. **About**: IDERIAとは。**教育的な価値のあるゲームづくり**を主な活動とする制作団体。短期記憶力の向上やASMRのリラックス効果など、遊ぶことが学びや心の変化につながる作品をつくる。あわせて、経験のない小中高生を対象としたVR体験活動・公開講座も行う。代表: 永野斗遠（九州情報大学大学院）。**団体名の由来も表示する**（§6）。
2a. **メンバー**: メンバーごとのカード。**担当と、そのメンバーの功績（受賞・制作・発表・論文）を一覧できる**こと。功績は `data.js` の `awards` / `works` / `talks` / `papers` の各項目にある `by[]` に `members[].id` を書くことで自動的に集まる。**同じ功績を二重に持たない**（データ源は `by[]` の1か所）。
3. **作品**（メインコンテンツ）: 作品No.付きカード。**「図鑑」という言い方は使わない**（安っぽく見えるため。見出し・ナビ・ボタンとも「作品」で統一する）。クリックで詳細（説明・関連リンク）が開く。§6のデータを使用。
   - **図版は作品ごとに必ず描き分ける。** 一覧したときに視覚で区別できることが条件。§6に画像URLがある作品はその画像、無い作品は作品の内容をモチーフにしたオリジナルの図版（SVG）を作品ごとに用意する。全カードが同じ絵になる実装は不可。
   - 実際のスクリーンショットが用意できたら `assets/works/<No>.png` に置き、`data.js` のその作品の `image` にパスを書けば差し替わる。（存在しないファイルを毎回探しに行かせないため、ロゴのような自動探索はしない）
   - **カード表面に、開かなくても中身が分かるひと言を出す**（v2.2）。`desc` の1文目（最初の「。」まで）をそのまま使い、2行を超えたら省略する。カードの開閉ボタンの読み上げ名にも同じ文を含める。
   - 各作品に `#work-01` 形式の直リンクを持たせ、その URL で開いた状態にできること。
4. **活動**: ゲームジャムの企画運営（第1〜4回＋高校での実施）・高大連携プロジェクト・VR体験会。詳細はアーカイブの活動ページへリンク。
5. **受賞・実績**: §6のとおり。**受賞は表彰ごとに1件ずつ分けて出す**（まとめない）。裏づけになる公式ページがあるものはリンクを付ける。受賞の下に「学会発表」「論文」の一覧を置く（データが無ければ見出しごと出さない）。
6. **お知らせ**: `data.js` の news 配列から新しい順に表示。年別に折りたたみ。**追記だけでページに反映**される構造にする。
7. **関連サイト**: フッターの上に置く。サイト名＋1行紹介のカード形式。§6の「関連サイト」のデータを使用。
8. **フッター**: 直前の「関連サイト」と同じリンクを繰り返さない。サイト内の各セクションへの目次と、SNS枠（空欄なら非表示・data.jsで管理）を置く。外部サイトへの導線は§3-7の「関連サイト」が担う。

## 4. 遊び要素・便利機能

- 作品カードのフリップまたは展開演出（ページをめくる感じ。過剰にしない）。開閉の合図（「詳細をひらく／とじる」）を文字で明示する。
- 作品の「収録数」表示。数字の意味が一目で分かる書き方にする（例: `閲覧中 No.03 / 全07作品`）。「すべてひらく／とじる」も用意する。
- お知らせの年別表示・「NEW」バッジ（30日以内の記事）。年が1つしかないときは折りたたみの案内を出さない。
- ページ内ジャンプ目次（About/メンバー/作品/活動/受賞/お知らせ/関連サイト）。**スマホでは全項目に必ず到達できること**（横スクロールで見切れる実装は不可。目次ボタン＋シートで開く方式にする）。
- ダーク/ライト切替（既定はOS設定）。切替時に `theme-color` も追随させる。
- 一定量スクロールしたら「ページ上部へ」ボタンを常設表示する。
