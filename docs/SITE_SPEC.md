## 1. 目的と対象

- 制作団体 **IDERIA**（代表: 永野斗遠）の公式サイト。「何を作っている団体か」が作品で伝わること。
- 読む人: 連携先の学校・大学関係者、コンテスト関係者、活動に興味を持った学生。
- 学習アーカイブ（https://109mei.github.io/game-learning-archive/）とは役割分担: アーカイブ=遊ぶ・学ぶ場、公式サイト=団体の顔。

## 2. デザインコンセプト —「アイデアの工房」

参考にした構造: 竹書房「メイドインアビス」公式サイトのアビスガイドページ（図鑑的なカード・縦に進む構成・ジャンプ目次・没入感）。**著作物（画像・キャラ・固有名詞・意匠の模倣）は一切使わない**。仕組みだけを借り、世界観はオリジナル。

- 世界観: アイデアが生まれて作品になっていく「工房」。ダークトーンの作業場に、作品カードが図鑑のように並ぶ。
- アクセントカラーは工房の灯りをイメージした暖色（アンバー＝琥珀色系）を1色決めて統一。ライトモードでも破綻しない。
- 単一ページ（`index.html`）＋データ分離（`data.js`）。依存パッケージなし・vanilla JSのみ。`prefers-reduced-motion` 対応。
- ロゴ: 当面はタイポグラフィ（文字組み）で「IDERIA」を表現。**ロゴ画像の差し替え枠**を用意しておく（`assets/logo.png` が存在すれば自動でそちらを表示する実装）。

## 3. ページ構成（上から順）

1. **ヒーロー**: IDERIA ロゴタイポ＋キャッチコピー（案: 「アイデアを、遊べるかたちに。」— 変更したければこの仕様書を修正）＋「作品図鑑を見る」ボタン。
2. **About**: IDERIAとは。ゲーム・教材の企画制作を行う団体。代表: 永野斗遠（九州情報大学大学院）。高校・大学と連携した制作活動（高大連携）を実施。
3. **作品図鑑**（メインコンテンツ）: 図鑑No.付きカード。クリックで詳細（説明・関連リンク）が開く。§6のデータを使用。
   - **図版は作品ごとに必ず描き分ける。** 一覧したときに視覚で区別できることが図鑑の条件。§6に画像URLがある作品はその画像、無い作品は作品の内容をモチーフにしたオリジナルの図版（SVG）を作品ごとに用意する。全カードが同じ絵になる実装は不可。
   - 実際のスクリーンショットが用意できたら `assets/works/<No>.png` に置き、`data.js` のその作品の `image` にパスを書けば差し替わる。（存在しないファイルを毎回探しに行かせないため、ロゴのような自動探索はしない）
   - 各作品に `#work-01` 形式の直リンクを持たせ、その URL で開いた状態にできること。
4. **活動**: ゲームジャムの企画運営（第1〜4回＋高校での実施）・高大連携プロジェクト・VR体験会。詳細はアーカイブの活動ページへリンク。
5. **受賞・実績**: §6のとおり。
6. **お知らせ**: `data.js` の news 配列から新しい順に表示。年別に折りたたみ。**追記だけでページに反映**される構造にする。
7. **関連サイト**: フッターの上に置く。サイト名＋1行紹介のカード形式。§6の「関連サイト」のデータを使用。
8. **フッター**: 直前の「関連サイト」と同じリンクを繰り返さない。サイト内の各セクションへの目次と、SNS枠（空欄なら非表示・data.jsで管理）を置く。外部サイトへの導線は§3-7の「関連サイト」が担う。

## 4. 遊び要素・便利機能

- 作品カードのフリップまたは展開演出（図鑑をめくる感じ。過剰にしない）。開閉の合図（「詳細をひらく／とじる」）を文字で明示する。
- 図鑑の「収録数」表示。数字の意味が一目で分かる書き方にする（例: `閲覧中 No.03 / 全07作品`）。「すべてひらく／とじる」も用意する。
- お知らせの年別表示・「NEW」バッジ（30日以内の記事）。年が1つしかないときは折りたたみの案内を出さない。
- ページ内ジャンプ目次（About/図鑑/活動/受賞/お知らせ/関連サイト）。**スマホでは全項目に必ず到達できること**（横スクロールで見切れる実装は不可。目次ボタン＋シートで開く方式にする）。
- ダーク/ライト切替（既定はOS設定）。切替時に `theme-color` も追随させる。
- 一定量スクロールしたら「ページ上部へ」ボタンを常設表示する。

## 7. お知らせの追記手順（運用ルール）

1. `data.js` の `news` 配列の先頭に `{ date: "2026-10-01", title: "◯◯しました", body: "任意の本文", url: "任意" }` を足す。
2. まずこの仕様書の§6にも同じ内容を1行追記する（仕様書=正の原則）。
3. `feed.xml` の先頭の `<item>` にも同じ内容を1件足す（購読者向け。ビルド工程を作らない方針のため手作業で揃える）。
4. コミットしてpushすれば反映される。

## 8. 検証チェックリスト（実装タスクの完了条件）

**表示・内容**
- [ ] PC/スマホ幅・ダーク/ライトで表示が破綻しない（320・390・768・1440px で横スクロールが出ない）
- [ ] §6にない情報・§5の禁止情報が含まれていない
- [ ] リンク切れなし（アーカイブへの各リンクを実際に確認。§6のURLが404なら正しいURLに差し替えてこの仕様書も直す）
- [ ] 作品図鑑の7枚が一覧で見分けられる（同じ絵が並んでいない）
- [ ] 誤字・文字化け・要素の重なりがない

**差し替え枠**
- [ ] `assets/logo.png` を置いたらロゴが差し替わる（無い状態ではタイポ表示）
- [ ] `assets/works/<No>.png` を置いて `data.js` の `image` に書いたら作品の図版が差し替わる

**アクセシビリティ**
- [ ] `prefers-reduced-motion` でアニメーション停止
- [ ] axe-core の違反が0件（ダーク・ライト両方）
- [ ] 文字と背景のコントラストが 4.5:1 以上（大きい文字は 3:1 以上）
- [ ] タップできる要素が 44×44px 以上
- [ ] 見出しだけをたどって作品7件に到達できる
- [ ] キーボードだけで全機能を操作できる

**壊れにくさ**
- [ ] JavaScriptが動かない環境でも、何のサイトか分かる案内と主要リンクが出る
- [ ] `color-mix()` など新しいCSSに未対応のブラウザでも、固定ヘッダーなどが破綻しない

## 9. 配信・品質要件

- **OGP**: `assets/ogp.png`（1200×630）を用意し、`og:image` / `twitter:card` を設定。SNSや連絡ツールに貼ったときにカードが出ること。
- **構造化データ**: JSON-LD の `Organization` を1つ埋め込む（団体名・URL・ロゴ・代表者）。内容は§6の範囲に限る。

- **`feed.xml`**: お知らせのRSS。§7の手順で手作業更新する。
- **`assets/apple-touch-icon.png`**（180×180）を置く。
